# LB-060 public rustpush build

Status: public compilation is unblocked. Genuine FairPlay signing remains a
separate production task in LB-064.

## Pinned source and original failure

LiteBubbles vendors `OpenBubbles/rustpush` as a recursive submodule at
`f35c4ee062b3c3eae54dc96b89b90ee99f5e1d0c`. The audited upstream
`src/activation.rs` used `include_bytes!` for these ten certificate/private-key
pairs:

```text
4056631661436364584235346952193
4056631661436364584235346952194
4056631661436364584235346952195
4056631661436364584235346952196
4056631661436364584235346952197
4056631661436364584235346952198
4056631661436364584235346952199
4056631661436364584235346952200
4056631661436364584235346952201
4056631661436364584235346952208
```

Each name was referenced at compile time as both `.crt` and `.pem`; the files
were absent from the public checkout. The activation code uses them to sign
the Apple device-activation request. They are not the IDS validation data
generated by the later Mac validation path.

## Public-build patch

`patches/rustpush/0001-public-build-no-source-tree-fairplay.patch` is a small,
auditable patch applied by `scripts/prepare-rustpush.sh`. It:

* adds rustpush's explicit `dummy-fairplay` feature;
* removes the ten source-tree `include_bytes!` requirements; and
* makes both the default public build and the dummy build return a typed
  runtime error when activation reaches the FairPlay signer.

No certificate, private key, or proprietary binary is stored in LiteBubbles.
The dummy feature is exposed by the backend as
`development-dummy-fairplay` and is intended only for compile/mock checks.
It cannot activate Apple services.

The normal development sequence is:

```sh
./scripts/prepare-rustpush.sh
cargo build --workspace
cargo test --workspace
```

The preparation script verifies the submodule commit, initializes nested
submodules over anonymous HTTPS when necessary, rejects unexpected local
changes, and applies the patch idempotently. CI runs the same script. The
direct `cargo` commands do not download or create FairPlay material.

## Deliberate production boundary

The default build now compiles and links rustpush, but it does not claim Apple
activation. A production signer/provider must be connected before
`rustpush::activation` can contact Apple's device-activation endpoint. That
provider work is tracked separately in LB-064 so a missing private resource
cannot block public backend, UI, or CI development and cannot be mistaken for
working Apple credentials.
